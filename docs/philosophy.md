# Philosophy

The concepts that shape the system.

## The Pillars

The four principles the system rests on.

- Specs & Checks
- Layering
- Harmony
- Shepherding

## Specs & Checks

A specification answers one question: what do you want? A check answers the next: is this what you said you wanted? Both questions hold for a painting or a book as much as for software. Done means demonstrated.

- Write before building
- Functional docs apart from technical docs
- Every case verified
- Demos over status reports
- Knowledge filed where it belongs

## Layering

Everything has a place, every piece is small, and every layer comes in order. Layers run in three directions: across responsibilities, down from an overview to a detail, and forward through time. A small piece can be read, verified and replaced.

- One purpose per file
- One step per change
- Prerequisites before features
- Converge only once proven

## Harmony

Harmony is tension held in balance. Two forces pull in opposite directions, and neither wins. A suspension bridge stands because of tension, and so does a project.

The tension lives between rules: brevity pulls at completeness, and strictness pulls at pragmatism. The tension lives between the three workers as well. Creative humans pull toward change, and rigid systems pull toward what was written. Hardworking agents do the work in between, held by both.

Keep both sides of a tension. Decide for the case at hand, and say why. Dropping one side breaks the bridge, and averaging the two produces mush.

- Conflicts surfaced and settled
- Deliberate trade-offs

## Shepherding

Shepherding is guidance built into the environment. Work takes the shape of its environment, so guardrails in the way of working make the right move the obvious move.

The strongest guardrail is an example. An agent repeats what the agent reads, so every page follows the rules the page states. The docs of the system are written by the system's own standards.

A rule followed everywhere stops needing attention. The rule becomes a habit, and the habit becomes character.

Strictness is a kindness: every removed choice removes a debate, and then a mistake. An agent wants to produce, and a guardrail makes the agent wait until the human knows what is wanted. A fence that lives in one head fades, so every fence is written down.

A rule can still be broken. A rule is called a rule because a suggestion was skipped too easily, so breaking the rule stays possible and gets harder. As agents grow, the strictness can fade. The strictness of a rule is a tension too, held in balance like every other.

- Lead by example
- Conventions enforced by tooling
- Written ways of working
- Strict defaults
- One obvious path per task

## The Chair Test

A pillar earns its place by removal, the way a chair shows which legs it needs.

- Without Specs & Checks there is no shared truth.
- Without Layering the work arrives big, late and unverifiable.
- Without Harmony the rules tear each other apart.
- Without Shepherding the other three need enforcing forever.

Four legs, no spares.

## The Benefits

- The project has one shared truth, and the checks keep that truth honest.
- A conflict between two rules is settled once, in the open.
- A mistake becomes a rule or a check, so the same mistake happens once.
- The human is free for judgment, taste and creation.

Distributed layers of harmonic tension that guide your project.
