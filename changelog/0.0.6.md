# 0.0.6

Healing is a choice in the onboarding, every rule has one home, and the tools are specs a project builds. Nothing in it is stable yet.

- 203 standards in 21 modules: five added and 196 changed
- Healing is automatic by default: a subagent strengthens the harness outside the task, and the report names the change for a veto. A project can choose to have the change filed for the director's review instead
- A contributor chooses whether an issue for coentrify waits for the director, or is filed on its own
- A healing log keeps every change automatic healing made, until the director rules on it
- Dev Tiers is the recommended order, and a pick that skips open bugs or debt gets a reminder
- A rule lives on one page, and every other page links to it
- Read First is now Core Rules: the rules every task follows, held to like a check
- The simple workflow keeps its lists in docs/development, like the tickets workflow
- Every word in a heading is capitalized, and the lint checks it
- The examples left over from one project are generic
- Coentrify ships no code a project has to keep: every check and helper is a spec with the cases it has to pass, and only the update and unlink scripts run from the source
- The builder has a page of its own: its tickets stack, and rebase onto main after each commit
- A page past its word budget can be accepted, with a reason, in its module's budget-exceptions.json
- Every version is checked for content left over from one project before it ships
