# 0.3.1

A round of filings from projects at work: no attribution in a commit, a ticket's id as the scope of every commit made for it, the greeting back to its essence, and an issue link shown as code printed it.

- 260 standards in 23 modules: four changed
- A commit-msg hook refuses attribution, from the new Attribution Check spec, since a cloud session's harness asks for it on its own
- Migration: a project on the Commits module builds the Attribution Check from its spec
- Every commit is a conventional commit, and a ticket's commits take its id as the scope: `feat(FEAT-123): description`, where the id used to stand in front
- The Ticket Id Check gets a spec, and a check a standard asks for without a spec is built from the standard's own words
- Migration: a project on the tickets workflow switches its commit message hook to the new form and builds the Ticket Id Check. Its history keeps the old form
- Greet goes back to its essence: the greeting opens the first reply to any command, the banner written out in full, every line, never only its tagline and never only in a tool's output
- `npx coentrify` prints Greet's own instruction beside the banner, so the two never drift
- Migration: a project's entry point says that a command opens with the greeting, before the session check
- A prefilled issue link reaches the director in the chat, copied whole from what `issue-link.mjs` printed, never typed out or pieced together
