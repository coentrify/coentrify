# 0.0.8

A second sweep of every page. Nothing in it is stable yet.

- 201 standards in 21 modules: twenty changed
- The update script runs as written, on Python 3.9 and up
- An update carries a changed overview line, and names every changed tool spec to rebuild from
- The unlink script drops the overview line of a standard the project did not adopt
- The coentrify.json example keeps the healing log its automatic healing writes to, and the page names the values of `workflow` and `records`
- An idea takes the Always modules of the recommendations and a workflow, and the stack modules join once it is built
- The first prompt in a fresh project carries the source. Once it is set up, the entry point leads to the commands at the source: a project that is set up adds that to its entry point
- A standard from coentrify that a project changes, by healing too, turns customized, and a game's new law goes in its own docs
- The commit gate refuses a piped check saved to a variable, and passes the shape the standard teaches and a tag listing with `--sort`
- A story lands on main whole once its tickets are done, in one merge commit that carries its id: the simplified release workflow. A project on the tickets workflow rebuilds its pick script as the merge script of the Landing spec
- A builder rebases its story onto main and runs the main checks green before it merges, so the conductor only merges
- A violation the change introduced is fixed. One that was there, small and obvious in a touched file, is fixed too. One that is complex or out of scope is noted as debt. A fix of what was there is named for a veto
- The docs are synced with the build and land with the story. The director's feedback on an agent's decision comes back as rework
- Content an agent fills in is written and named for a veto. An impactful change, one that adds scope or moves a rule or a decision away from the director, is discussed first
- A rename updates every reference at once, and a changed convention sweeps its existing occurrences as debt. A pattern from a review goes to healing
- Automatic filing files at once, and a change to a module with a source of its own reaches coentrify only when it is generic, as an addition
- In the tickets workflow, healing files a heal ticket, `HEAL-1`, which carries its go when healing is automatic
- Work that changes what the user sees or hears is filed as a feature or a bug, never as debt
