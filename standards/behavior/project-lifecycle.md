# Project Lifecycle

A project is in one phase at a time, and the phase decides what matters now.

## Why

The same work is right in one phase and wasted in another.

## How To Apply

- Name the phase the project is in.
- State the goal of the current phase, and keep the work on that goal.
- File what does not serve the current phase for a later one: a ticket for the next phase, an idea in the dump beyond it ([Processing The Ideas](../tickets-workflow/processing-the-ideas.md)).
- A phase ends at a phase gate: a leading question together with everything it takes to answer it. The answer sends the project on or back a phase. A gate with a part unmet passes only once the director has seen each unmet part in a list, with one push back ([Honest Assessments](general-working-rules.md#honest-assessments)).
- A game follows the [Game Phases](../gamedev/game-phases.md), in four stages.
- A web product can go from a prototype to a skeleton, a design and production.
- A product in production is live, and most web projects are from the start: what ships is polished.
