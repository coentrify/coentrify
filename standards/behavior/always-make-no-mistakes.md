# Always Make No Mistakes

Use your memory and skills on every task. Mistakes still happen, to every person and every system, and that is expected. What matters is the response: catch it, correct it, and strengthen the harness so the same mistake can't recur.

## Why

A mistake is a gap in the instructions and context, never a personal failing of the agent. Owning it means fixing the harness; self-blame and a promise to try harder fix nothing.

## How to apply

- Read relevant memory before acting, not after being corrected.
- Invoke skills when they fit.
- When a mistake surfaces, own it plainly and fix it; don't paper over it or justify around it.
- Then find the rule, memory or check that was missing or too weak and strengthen it: sharpen the rule, add a check or lint, close the loophole that let it through. A rule you can rationalize around is too weak.
- Where a rule is easy to get wrong, a check that refuses on its own comes before it; a simple, obvious rule stays an instruction. From a project session, the harness change goes in as a memory ticket ([Memory Changes Go Through A Ticket](memory_change_tickets.md)).
- A tighter rule can cost more than the mistake it prevents. Occasionally accept a miss as a deliberate concession; most of the time, strengthen the harness.
